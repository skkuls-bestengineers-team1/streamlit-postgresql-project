# 영화 정보 ERD

KOBIS 영화 데이터를 기준으로 한 논리 모델입니다.

- **PK**: 기본키
- **FK**: 외래키 (`영화명` → `영화_마스터.영화명`)
- **배급**: 영화 1건에 배급사 N개 → 복합키 `(영화명, 배급사)`
- **제작 / 매출**: 영화 1건당 1행 → `영화명`이 PK이자 FK

```mermaid
erDiagram
    영화_마스터 ||--o{ 영화_배급 : "배급한다"
    영화_마스터 ||--|| 영화_제작 : "제작된다"
    영화_마스터 ||--|| 영화_매출 : "매출을_가진다"

    영화_마스터 {
        string 영화명 PK
        string 영화명_영문
        date 개봉일
        int 제작연도
        string 유형
        string 장르별제작상태
        string 대표국적
        string 국적
        datetime 수정일자
        string 수정자
        datetime 최초일자
        string 최초수정자
    }

    영화_배급 {
        string 영화명 PK_FK
        string 배급사 PK
        datetime 수정일자
        string 수정자
        datetime 최초일자
        string 최초수정자
    }

    영화_제작 {
        string 영화명 PK_FK
        int 제작연도
        string 제작상태
        string 감독
        string 제작사
        datetime 수정일자
        string 수정자
        datetime 최초일자
        string 최초수정자
    }

    영화_매출 {
        string 영화명 PK_FK
        decimal 매출액
        decimal 매출액_점유율
        decimal 누적_매출액
        int 관객수
        int 누적관객수
        int 스크린수
        int 상영횟수
        datetime 수정일자
        string 수정자
        datetime 최초일자
        string 최초수정자
    }
```

## 관계 요약

| 부모 | 자식 | 카디널리티 | 조인 키 |
|------|------|------------|---------|
| 영화_마스터 | 영화_배급 | 1 : N | `영화명` |
| 영화_마스터 | 영화_제작 | 1 : 1 | `영화명` |
| 영화_마스터 | 영화_매출 | 1 : 1 | `영화명` |

## 키 정의

| 테이블 | PK | FK |
|--------|----|----|
| 영화_마스터 | `영화명` | - |
| 영화_배급 | `(영화명, 배급사)` | `영화명` → 영화_마스터 |
| 영화_제작 | `영화명` | `영화명` → 영화_마스터 |
| 영화_매출 | `영화명` | `영화명` → 영화_마스터 |

## 참고

- `장르별제작상태`는 요청 스키마 그대로 단일 컬럼으로 표기했습니다. 장르/제작상태를 분리하려면 별도 컬럼 또는 코드 테이블로 정규화할 수 있습니다.
- 감사 컬럼(`수정일자`, `수정자`, `최초일자`, `최초수정자`)은 네 테이블 공통입니다.
